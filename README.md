# Pixel Dungeon Survivor

Pixel Dungeon Survivor - небольшая 2D игра в жанре top-down survival shooter, написанная на C++17 с использованием SFML 3.0. Игрок управляет рыцарем на арене подземелья, переживает волны скелетов, переключается между мечом и луком, собирает аптечки и бустеры, а также пытается побить сохраненный рекорд выживания.

Основная графика может загружаться из texture atlas:

```text
assets/textures/dungeon_atlas.png
```

Из этого файла берутся только тайлы карты: пол, стены и элементы оформления подземелья. Персонажи, враги, аптечки, зелья и бустеры остаются пиксельными и рисуются примитивами SFML. Если atlas отсутствует, игра не падает и использует резервную отрисовку карты примитивами SFML.

## Возможности

- Главное меню, игровой режим и экран Game Over.
- Камера сверху с `sf::View`, которая следует за игроком.
- 2D рыцарь с управлением через `W`, `A`, `S`, `D`.
- Переключение оружия через `Q` или `Tab`.
- Атака мечом с видимым пиксельным замахом.
- Атака луком с летящими стрелами.
- Волны скелетов с растущей сложностью.
- Бронированные скелеты после 5 минут.
- Скелеты-маги после 3 минут, максимум 2 мага за волну.
- Полоски здоровья над врагами.
- Аптечки.
- Бустеры скорости передвижения.
- Бустеры прокачки оружия на урон и скорость атаки.
- Таймер выживания и сохранение лучшего времени.
- Текстурные тайлы подземелья для пола, стен и декора карты.

## Управление

| Клавиша / мышь | Действие |
| --- | --- |
| `W`, `A`, `S`, `D` | Движение |
| Положение мыши | Прицеливание / направление взгляда |
| `Space` или левая кнопка мыши | Атака |
| `Q` или `Tab` | Переключить оружие |
| `Enter` в меню | Начать игру |
| `Esc` во время игры | Вернуться в главное меню |

## Требования для сборки

- Компилятор C++17.
- CMake 3.22 или новее.
- SFML 3.0, не SFML 2.x.
- Используемые модули SFML:
  - `Graphics`
  - `Window`
  - `System`

Проект настроен на локальную копию SFML в папке:

```text
SFML/
├── include/
├── lib/
├── bin/
└── lib/cmake/SFML/SFMLConfig.cmake
```

В `CMakeLists.txt` специально используется:

```cmake
set(SFML_DIR "${CMAKE_SOURCE_DIR}/SFML/lib/cmake/SFML")
find_package(SFML 3.0 REQUIRED COMPONENTS Graphics Window System)
```

Проект не использует vcpkg, Conan, FetchContent или системную установку SFML.

## Сборка через CMake / MinGW

Из корня проекта:

```powershell
cmake -S . -B build -G "MinGW Makefiles"
cmake --build build
.\build\PixelDungeonSurvivor.exe
```

После каждой сборки CMake копирует DLL-файлы SFML из `SFML/bin` рядом с исполняемым файлом. Если используется MinGW, также копируются распространенные runtime DLL:

- `libstdc++-6.dll`
- `libgcc_s_seh-1.dll`
- `libwinpthread-1.dll`

## Сборка в CLion

1. Открой корневую папку проекта в CLion.
2. Убедись, что выбран CMake target `PixelDungeonSurvivor`.
3. Выбери MinGW toolchain, совместимый со сборкой SFML.
4. Выполни **Reload CMake Project**.
5. Собери и запусти `PixelDungeonSurvivor`.

Если CLion не находит SFML, проверь, что существует файл:

```text
SFML/lib/cmake/SFML/SFMLConfig.cmake
```

Если файла нет, скопируй SFML 3.0.2 в проект:

```powershell
Copy-Item -Recurse "C:\c++ libraries\SFML-3.0.2" ".\SFML"
```

После этого перезагрузи CMake.

## Как файлы взаимодействуют друг с другом

Центральный класс проекта - `Game`. Он владеет окном SFML, текущим состоянием игры, игроком, картой, менеджером волн, менеджером рекордов, врагами, снарядами, аптечками, бустерами скорости и бустерами оружия.

Основной цикл выглядит так:

```text
main.cpp
  создает Game
    Game::run()
      handleEvents()
      update(dt)
      draw()
```

Во время `update(dt)` класс `Game` обновляет движение игрока, врагов, снарядов, волн и предметов, проверяет столкновения и переводит игру в Game Over, если игрок погиб.

Во время `draw()` класс `Game` выбирает, что рисовать, в зависимости от текущего состояния:

- `MainMenu`
- `Playing`
- `GameOver`

## Описание header/source файлов

### `main.cpp`

Создает объект `Game` и запускает игровой цикл. Также записывает небольшой файл `run_log.txt`, чтобы можно было понять, на каком этапе возникла проблема, если исполняемый файл закрывается сразу после запуска.

### `CMakeLists.txt`

Описывает сборку проекта: создает executable, включает C++17, ищет SFML 3.0 в локальной папке `SFML`, линкует `SFML::Graphics`, `SFML::Window`, `SFML::System` и копирует нужные DLL после сборки.

### `include/Common.hpp`

Содержит общие enum-ы и вспомогательные функции:

- `GameState`
- `WeaponType`
- расчет длины вектора и нормализация
- создание прямоугольников и проверка пересечений
- объявление `formatTime(float seconds)`

### `include/Game.hpp` / `src/Game.cpp`

Координирует всю игру.

Отвечает за:

- создание `sf::RenderWindow`
- хранение `sf::View` для камеры и интерфейса
- загрузку texture atlas через `TextureAtlas`
- обработку событий SFML 3.0 через `std::optional<sf::Event>`
- переключение между меню, игрой и Game Over
- обновление игрока, врагов, снарядов, предметов и волн
- проверку столкновений
- спавн аптечек, бустеров скорости и бустеров оружия
- сохранение рекорда через `RecordManager`
- отрисовку подземелья, персонажей, эффектов и HUD

Важные методы:

- `run()`
- `handleEvents()`
- `update(float dt)`
- `draw()`
- `resetGame()`
- `tryAttack()`
- `checkCollisions()`
- `spawnHealthPack()`
- `spawnSpeedBooster()`
- `spawnWeaponBooster()`
- `finishGame()`

### `include/TextureAtlas.hpp` / `src/TextureAtlas.cpp`

Загружает общий spritesheet/texture atlas:

```text
assets/textures/dungeon_atlas.png
```

Класс хранит `sf::Texture` и набор прямоугольников `sf::IntRect`, которые указывают, где на изображении находятся нужные тайлы:

- тайлы пола
- тайлы стен
- варианты углов/фрагментов стен

Сейчас `TextureAtlas` используется только картой (`DungeonMap`). Персонажи, враги и предметы специально оставлены на примитивной пиксельной отрисовке.

Если файл atlas не найден, текстурный режим карты не включается. Игра не создает собственный PNG или fallback-atlas автоматически.

### `include/Player.hpp` / `src/Player.cpp`

Описывает рыцаря.

Хранит:

- позицию и размер
- здоровье и максимальное здоровье
- скорость движения
- текущее направление взгляда
- выбранное оружие
- cooldown атаки
- таймер буста скорости движения
- уровень урона оружия
- уровень скорости атаки

Игрок читает состояние клавиатуры для движения и использует `DungeonMap::isBlocked()`, чтобы не проходить сквозь стены.

Игрок всегда рисуется пиксельными примитивами SFML, независимо от наличия texture atlas.

### `include/Weapon.hpp` / `src/Weapon.cpp`

Описывает иерархию оружия.

`Weapon` - базовый интерфейс. `Sword` и `Bow` реализуют конкретное поведение оружия.

`Sword`:

- имеет короткий cooldown
- наносит в 2 раза больше базового урона, чем лук
- создает прямоугольную область ближней атаки перед игроком
- рисует видимый пиксельный замах мечом

`Bow`:

- имеет более длинный cooldown
- создает стрелы типа `Projectile`
- учитывает прокачку урона игрока при выстреле

### `include/Projectile.hpp` / `src/Projectile.cpp`

Описывает летящие снаряды.

Используется для:

- стрел игрока
- магических снарядов скелетов-магов

Снаряд хранит:

- позицию
- направление
- скорость
- максимальную дистанцию
- урон
- принадлежит ли он врагам
- состояние жив/уничтожен

Вражеские снаряды рисуются фиолетовыми цветами и наносят урон игроку. Снаряды игрока наносят урон врагам.

### `include/Enemy.hpp` / `src/Enemy.cpp`

Базовый интерфейс врага.

Описывает общее поведение:

- здоровье и максимальное здоровье
- получение урона
- проверку смерти
- отношение текущего здоровья к максимальному для HP-бара
- опциональное поведение брони
- опциональное поведение мага/стрельбы

`Game` хранит врагов так:

```cpp
std::vector<std::unique_ptr<Enemy>>
```

Это позволяет обычным скелетам и скелетам-магам находиться в одном контейнере.

### `include/Skeleton.hpp` / `src/Skeleton.cpp`

Описывает два типа врагов:

- `Skeleton`
- `MageSkeleton`

`Skeleton`:

- преследует игрока
- пытается обходить стены
- не заходит внутрь тела игрока
- рядом с игроком двигается сбоку, а не накладывается прямо на него
- становится бронированным после 5 минут или если появился после этого времени
- рисует тело, голову, кости, броню и полоску здоровья
- рисуется пиксельными примитивами SFML

`MageSkeleton`:

- появляется после 3 минут
- максимум 2 мага за волну
- держит дистанцию от игрока
- двигается вбок во время прицеливания
- стреляет в игрока вражескими снарядами
- имеет видимую робу, капюшон, посох и магический кристалл
- рисуется пиксельными примитивами SFML

### `include/WaveManager.hpp` / `src/WaveManager.cpp`

Управляет волнами врагов.

Отвечает за:

- хранение номера текущей волны
- паузу между волнами
- увеличение сложности со временем
- спавн обычных скелетов
- спавн скелетов-магов после 3 минут
- создание бронированных врагов после 5 минут

Каждая следующая волна сложнее предыдущей. Время выживания также повышает сложность.

### `include/DungeonMap.hpp` / `src/DungeonMap.cpp`

Создает и рисует подземелье.

Отвечает за:

- размер карты
- прямоугольники стен
- декоративные прямоугольники
- отрисовку пола с пиксельной сеткой
- отрисовку текстурных тайлов пола и стен, если доступен atlas
- резервную отрисовку пола, стен и неровных сколов примитивами, если atlas не найден
- декор вроде камней, колонн и факелов
- проверку столкновения прямоугольника со стенами
- выдачу случайных свободных позиций для спавна врагов и предметов

Коллизия основана на простых прямоугольниках. Визуальная часть карты может быть текстурной, но физика стен остается простой и стабильной.

### `include/HealthPack.hpp` / `src/HealthPack.cpp`

Описывает аптечки.

Аптечки:

- периодически появляются на карте
- лечат игрока
- исчезают после подбора
- рисуются как бело-красные пиксельные медицинские коробки

### `include/SpeedBooster.hpp` / `src/SpeedBooster.cpp`

Описывает бустеры скорости движения.

Бустеры скорости:

- периодически появляются на карте
- временно увеличивают скорость передвижения игрока
- рисуются как голубые пиксельные предметы
- исчезают после подбора

### `include/WeaponBooster.hpp` / `src/WeaponBooster.cpp`

Описывает бустеры прокачки оружия.

Бустеры оружия появляются после спавна волны и могут улучшить:

- урон оружия
- скорость атаки

Бустеры урона увеличивают урон. Бустеры скорости атаки уменьшают cooldown атаки, но с нижним пределом, чтобы атаки не становились слишком быстрыми.

### `include/Button.hpp` / `src/Button.cpp`

Простой класс кнопки интерфейса для меню.

Используется для:

- Play
- Play Again
- Main Menu
- Exit

Кнопки рисуются прямоугольниками и, если доступен шрифт, подписями через `sf::Text`.

### `include/RecordManager.hpp` / `src/RecordManager.cpp`

Загружает и сохраняет лучшее время выживания.

Файл рекорда:

```text
save/best_time.txt
```

Когда игрок погибает, `Game` вызывает `RecordManager::updateIfBest()`. Если новое время лучше старого, файл перезаписывается новым значением.

## Игровой процесс

1. Игра запускается в состоянии `MainMenu`.
2. Меню показывает название, лучший рекорд и кнопку Play.
3. Запуск игры вызывает `Game::resetGame()`.
4. `WaveManager` начинает создавать волны врагов.
5. `Game` каждый кадр обновляет игрока, врагов, снаряды и предметы с учетом delta time.
6. Игрок старается продержаться как можно дольше.
7. Если здоровье падает до нуля, `Game::finishGame()` переводит игру в состояние `GameOver`.
8. `RecordManager` сохраняет новый рекорд, если игрок побил старый.

## Особенности SFML 3.0

Код использует стиль обработки событий SFML 3.0:

```cpp
while (const std::optional event = m_window.pollEvent())
{
    if (event->is<sf::Event::Closed>())
        m_window.close();

    if (const auto* key = event->getIf<sf::Event::KeyPressed>())
    {
        // обработка клавиши
    }
}
```

Это отличается от привычного кода SFML 2.x:

```cpp
sf::Event event;
while (window.pollEvent(event))
```

Не переписывай проект на стиль событий SFML 2.x.

## Решение проблем

### `SFMLConfig.cmake not found`

Проверь, что в проекте есть файл:

```text
SFML/lib/cmake/SFML/SFMLConfig.cmake
```

Если его нет, скопируй SFML 3.0.2 в проект:

```powershell
Copy-Item -Recurse "C:\c++ libraries\SFML-3.0.2" ".\SFML"
```

После этого перезагрузи CMake.

### Игра сразу закрывается

Открой:

```text
run_log.txt
```

Если лог дошел до строки `Game object created. Entering loop.`, значит игра запустилась корректно. Проверь, что запускаешь target `PixelDungeonSurvivor`, и что окно не спряталось за IDE.

Если исполняемый файл не стартует из-за отсутствующих DLL, пересобери проект через CMake. Post-build команды копируют DLL SFML и MinGW рядом с `.exe`.

### `Permission denied` при линковке

Обычно это значит, что `PixelDungeonSurvivor.exe` все еще запущен. Закрой окно игры или останови процесс, затем собери проект заново.
